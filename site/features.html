Tune a local model

A model on your own machine runs in whatever memory you have. clyde tune tests the Ollama settings that can give it a longer window, less memory or more speed, keeps only the ones that leave what the model says unchanged, and shows you how to turn them on.

clyde tune

Clyde offers it when clyde setup finds a local model, and again after you download one with /models local. It loads the model a few times, so it takes a few minutes and always asks first.

What it does

  1. Asks what you use the model for. Coding, chat, research, long documents, quick answers (any mix), what matters most, and how much RAM to keep free. The answers are saved, so it asks once.
  2. Tests each setting on a private server. Ollama reads these settings only when it starts, so Clyde starts a throwaway ollama serve on another port for each one, loads your model at the window Clyde uses for it, and measures memory and speed. Yours is never touched.
  3. Checks what the setting did to the model. The same prompts are answered again, a fact buried in a long prompt is looked for, and the model has to make a tool call. A setting that changes what the model says is dropped, however much memory it saves.
  4. Picks one, or tells you to keep what you have. It chooses by your priority among the settings that passed, and only if the gain is worth restarting Ollama.

What it asks you

Mix as many as you like. They set how strict the quality check is and what it tries to win.

Coding and agents
Tool calls must stay right. The answers have to stay 95% alike, and the lossy cache is never tried.
Research and fact-checking
Answers must hold up over many sources: the same strict bar, plus the buried-fact check at the long window.
Long documents
Room for the text matters most. It looks for the longest window your memory can carry.
Chat and quick answers
Wording is more forgiving (80% alike), so the smaller cache is also tried.
What matters most
Speed, a long window, or reliability. It picks the winner by this, after the quality bar is met.
RAM to keep free
A setting that would leave less than this free for your other apps is dropped.

What a setting has to pass

No more memory
Never more than 2% above the default: the point is more room without more resources.
No real slowdown
Within the measurement noise (8%) of the default. Speed is the best of two runs, since one slow sample is just a busy machine.
Free RAM kept
It leaves at least what you asked to keep free, and stays inside the share of RAM a model may use.
Tool calling intact
The model still makes a correct tool call and uses the result, using Clyde's own model check.
Long-context recall
A fact buried in a long prompt (up to 24,000 tokens, at the window being tested) is still found.
Same answers
Fixed prompts answered with no randomness have to stay 95% alike (80% for chat). A cache that drifts shows up here first.
Worth a restart
It must free 5% of memory, open a 10% longer window, or run 5% faster. A smaller gain is not worth restarting Ollama for.

Where it runs

Setup
clyde setup offers it when it finds a local model. It never runs with --yes.
After a download
/models local offers it once the model is on disk, after the usual model check.
Any time
clyde tune. Add --ask to answer the questions again, --model NAME for a specific model, --ctx TOKENS to test one window.
Your own Ollama
If it has a model loaded, Clyde says so and asks before unloading it, so the readings are fair. Ollama keeps running and loads the model again on its next request.

Turning a setting on

Clyde prints the exact commands for how you run Ollama; it does not change your Ollama itself.

Ollama from the terminal
Add the variables to ~/.zshrc, for example export OLLAMA_KV_CACHE_TYPE=q8_0, then stop Ollama and start it again with ollama serve in a new terminal.
The Ollama app on a Mac
Run launchctl setenv OLLAMA_KV_CACHE_TYPE q8_0 (and the flash attention line), then quit and reopen the app. This only reaches the app, not an ollama serve you start yourself.
Linux with systemd
sudo systemctl edit ollama, add the variables under [Service], then sudo systemctl restart ollama.
A longer window
Also set the CLYDE_MODEL_CONTEXT_... variable it prints, so Clyde asks for that window.

What it can't do

  • It works with Ollama only, including models pulled from Hugging Face into Ollama. LM Studio does not let you set the cache type or flash attention from outside its app, so it is left out.
  • Ollama's hosted models can't be tuned, since the provider runs the server.
  • The quality check catches changes in what the model says, its tool calls and long-context recall. It does not judge writing quality.
  • It makes the model fit and run better. It does not make it smarter; that takes fine-tuning, which is a separate tool.
  • Only a Mac has been tested. The Linux commands are given but untried.

Checking which models work

/eval runs a tool call, a round trip and a hand of 11 graded tasks against every model your keys reach. Broken ones disappear from /models. The red line is a model that scored lower than at its last run.
